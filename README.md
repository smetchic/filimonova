# Филимонова

Веб-приложение ПТО.

## Текущая архитектура
- GitHub Pages — статический frontend.
- Supabase Auth — пользователи и сессии.
- Supabase PostgreSQL — рабочие данные.
- Supabase Storage — документы.

## Безопасность
Репозиторий публичный. Реальные данные объекта, исходные Excel/PDF, резервные копии JSON, пароли и secret/service-role keys сюда не загружаются.

В браузерном frontend хранится только Supabase Project URL и publishable key. Доступ к данным ограничивается Row Level Security в PostgreSQL.

## Первый запуск
Первичный глобальный администратор заранее разрешён на стороне Supabase. После регистрации и подтверждения email приложение автоматически определяет роль администратора и создаёт первый пустой проект «Филимонова», если его ещё нет.

## Структура кода
Сборки нет: `index.html` по порядку подключает обычные скрипты из `assets/app/`. Объявления верхнего уровня у них общие, поэтому каждый следующий файл может пользоваться функциями и переменными из предыдущих. Новый файл нужно добавить в `index.html` перед `18-main.js`.

| Файл | Что внутри |
|---|---|
| `01-core.js` | конфигурация, клиент Supabase, состояние интерфейса, форматирование, загрузка данных проекта, настройки объекта (`objectSettings`, `buildingSections`) |
| `02-tables.js` | фильтры, ширина и закрепление колонок, выделение ячеек с суммой и копированием |
| `03-material-card.js` | карточка материала |
| `04-render-common.js` | общие части экранов: контекстная панель, группы строк |
| `05-import-spec.js`, `06-import-estimate.js` | импорт спецификации и смет из Excel |
| `07-supplier-price.js` | прайс поставщика: импорт, сопоставление, контроль |
| `08-spec.js` | Спецификация |
| `09-estimates.js` | Сметы и текущие цены |
| `10-gpr.js` | ГПР |
| `11-supply.js` | Поставка и документы поставки |
| `12-montage.js` | Монтаж |
| `13-avr-s29.js` | АВР, КС‑6, С‑29 |
| `14-accounting.js` | бухгалтерские данные и связи кодов |
| `15-recon.js` | Сверка и журнал расхождений |
| `16-work-links.js` | Связи работ |
| `17-navigation.js` | переключение страниц и общие обработчики |
| `18-main.js` | вход, выход, боковое меню, выбор объекта и его настройки, запуск приложения |

Отдельно подключаются `ux-overhaul.js`, `material-card-compact.js` и `theme-settings.js`. Стили `table-ux.css` (подключаются последними) отвечают за закреплённые левые колонки, оттенки уровней группировки, строку «Всего» под шапкой, подсветку строки и выделение ячеек; сама логика закрепления и выделения лежит в `02-tables.js`.

`assets/templates/s29-blank.xlsx` — пустой бланк формы С‑29. Кнопка «Бланк С-29» заполняет его данными месяца: строка 28 бланка служит образцом строки таблицы. Реквизиты шапки (организация, кто утверждает, объект, МОЛ) пользователь вводит перед выгрузкой, браузер их запоминает.

Объектов может быть несколько. Объект выбирают щелчком по названию в левом верхнем углу; выбор запоминается в браузере. Там же администратор задаёт число секций и список локальных смет (номер, секция, зона). Эти настройки хранятся в `projects.settings`; по ним строятся фильтры секций, рабочая сводка, слоты импорта спецификаций и смет. Объект без настроек работает как раньше: две секции и сметы №200–203, 207.

## База данных
`supabase/migrations/` содержит всю историю схемы базы, начиная с первой миграции `filimonova_schema_v1`. Если применить файлы по порядку имён на чистом проекте Supabase, получится та же структура, что и у рабочей базы: таблицы, функции, политики RLS, триггеры и бакет хранилища. Данные в миграции не входят.

В миграции `bootstrap_primary_admin_email` вместо настоящего адреса администратора стоит заглушка `admin@example.com`. При развёртывании новой копии её нужно заменить.
